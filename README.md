# Boardline — очередь Брест → Тересполь

Небольшой сайт для мониторинга электронной очереди легковых автомобилей на пункте пропуска **Брест — Тересполь** и расчёта безопасного времени регистрации.

## Что собирается

- количество автомобилей в `carLiveQueue`;
- число прошедших автомобилей за час и сутки из `statistics`;
- изменение очереди, наблюдаемые регистрации и оценка притока с учётом фактического интервала сбора;
- средняя скорость за 6, 12 и 24 часа;
- таблица суточной динамики по последнему показателю `carLastDay` каждого дня;
- обезличенные времена регистрации и изменения записей;
- признаки повторившегося или потенциально устаревшего ответа API.

Номера автомобилей не записываются. Подробные обезличенные записи хранятся 72 часа, агрегированные точки — до 90 дней.

Основная рекомендация рассчитывается по фактической средней скорости за последние 24 часа (`carLastDay / 24`). Пользовательский запас добавляется ко времени прибытия отдельно. Значения 20, 24 и 30 авто/ч используются только как сравнительные сценарии.

## Локальный запуск

```bash
npm install
npm run collect
npm run dev
```

Сборка:

```bash
npm run build
```

## Автоматизация

Workflow `collect.yml` запускается каждые 30 минут (в 07 и 37 минут каждого часа), добавляет точку в `data/history.json` и сразу публикует обновлённые данные на GitHub Pages. `deploy-pages.yml` отдельно пересобирает сайт после обычных изменений исходного кода.

Первый запуск сборщика и публикацию также можно выполнить вручную во вкладке **Actions**.

## Ограничение свежести

`statistics` не возвращает собственную временную метку. Поэтому сайт не называет такой ответ достоверно свежим сам по себе: оценка выполняется по времени изменений из `monitoring-new`, повторяемости ответов и доступности обоих источников.
